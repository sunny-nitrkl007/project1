us792913 - Improve/Simplify DataLinkData (machas3)

Refactored DataLinkParam and DataLinkParamInfo to move all "static" metadata to DataLinkParamInfo and variable data to DataLinkParam. Made the following client-side changes:

  • DataLinkData::GetParams - Allows iteration through the internal container using C++11 range-based for loops. Usage (const is optional): for (const DataLinkParam& dlParam : dataLinkData.GetParams()) { switch (dlParam.GetParamId()) { …

  • DataLinkData::AddDataLinkParam - Now returns false if all necessary metadata for the parameter has not been set.

  • DataLinkData::UpdateDataLinkParam - Now returns false if the update failed.

  • DataLinkData::GetParamByID - New function that provides a pointer to the DataLinkParam with the provided PID and ParameterIdType. Overloads are provided if the Parameter comes from another source (i.e. SID/Source Address and DataLinkType)

  • DataLinkData::GetParamValueIndexByName, GetParamValueIndexByPID - Deleted, they were poorty implemented functions that returned 0 ( a valid index) if the parameter was not found.

  • DataLinkParam::SetLastValue - Can take either a vector<unsigned_8> or uint32_t for fixed length PIDs. In either case, lastValue should be the raw, unpacked value read from the datalink. DSI is required, i.e. lastValue cannot be set without the DSI and vice versa.

  • DataLinkParam::SetLastValueDsi – Removed per changes to SetLastValue

  • DataLinkParam::SetVarLengthParamValue - Sets the lastValue for variable length PIDs. Can take either a vector or uint8_t array.

  • DataLinkParam::SetLastValueEng - New function that allows the engineering value to be directly set for fixed length PIDs. Raw value is computed based on Scaling and Offset and stored internally. Simplifies internal publish of DataLinkData.

  • DataLinkParamInfo::GetDataLinkTypeString, GetParamIdTypeString,

    GetParameterTypeString, GetUnitsString, VarLengthDataLinkParamFactory

    GetVarLengthParamTypeString - New functions to get std::string representations for the corresponding data. Used for OCS plugin that will eventually appear in eta-ais, can also be used for debugging.

Fix remaining bytes to read is decremented twice for a single read (gundas1)

In "boost/cgi/cgi/request_service.hpp" in parse_post_vars(), the remaining bytes to read is decremented twice for a single read. Once in the client read_some, and once in the request service parst_post_vars. This is because a reference to the client bytes_left is used rather than a copy of the bytes left.

std::size_t& bytes_left (impl.client_.bytes_left_);

Should be std::size_t bytes_left (impl.client_.bytes_left_);

For content lengths that are not multiples of 128, the double decrement rolls over and the post data is read until the eof is encountered, possibly greater than the content length.
